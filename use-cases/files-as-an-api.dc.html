For data teams

Turn a bucket of Parquet into a queryable API

The lake has the data; the people who need it have a browser and curl. A DuckDB connection pointed at a prefix makes each file a view, locked to the paths you list, with no copy and no warehouse.

✓Parquet, CSV and JSON on S3, GCS, R2, HTTPS or disk. Hive-style key=value/ partitions become one view.
✓Nothing outside allowed_paths can be read, enforced by DuckDB itself as the connection opens.
✓Saved queries over the views get grants, masking and caching like any other.
✓Results back out as Parquet too, in steady memory at any size.
Guide 41: Publish files in S3 as an API →
Files as an API
# a connection of nothing but files
curl -X POST https://data.example.com/api/v1/connections \
  -H 'X-API-Key: <admin>' -H 'Content-Type: application/json' -d '{
  "name": "lake",
  "db": "duckdb",
  "database": ":memory:",
  "active": true,
  "allowed_paths": ["s3://acme-lake/events/", "s3://acme-lake/dim/"],
  "auto_views": true,
  "user": "${LAKE_ACCESS_KEY}", "password": "${LAKE_SECRET}", "region": "eu-west-1"
}'

# events/date=2026-10-10/*.parquet is now a table called events
SELECT date, count(*) FROM events GROUP BY 1 ORDER BY 1 DESC LIMIT 7
