0.21October 2026Release

Agents can write now. A person approves each write.

MCP write tools stop being a flat no. An agent proposes a write; it queues in the Console with the exact statement, the key that asked, and the connection it would touch. An administrator approves or rejects it, and both decisions land in the audit log. Per-agent usage is recorded alongside. Experimental, labelled as such in the product.

Design noteArchitecture

Why every front door runs the same eight steps

REST, MCP, server-sent events and the export CLI all call one engine. Identity, limits, grant, parameters, SQL guard, execution, masking, record: the order is fixed, and a step that fails stops the call with a typed error code. The point is that an AI agent cannot be governed less than an app just because it arrived through a different protocol.

Design noteOperations

One worker, many threads, and what Redis is actually for

/metrics is per process, so gunicorn runs one worker and scales with threads; capacity comes from more instances. Redis then does three things: one response cache warmed by any instance, one rate-limit budget instead of one each, and one event stream. If Redis blinks, a cached response is a miss and limits are counted per process for a few seconds. Never lifted, never turned into refusals.

SQL2API is now QueryAPIGate

The same project, renamed because sql2api was shared by a dozen unrelated projects. It is a clean break: package, command, import, environment variables, metrics prefix and Docker image all change. A server that still finds any SQL2API_* variable refuses to start and lists what to rename, rather than silently running without an API key.
