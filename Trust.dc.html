Trust center

Your data stays on your infrastructure. Everything else, you can check.

QueryAPIGate is software you run, not a service we host. This page collects what a security review asks for, with each claim pointing to where you can verify it: in the code, in CI, or on your own running server.

Your data

What QueryAPIGate keeps, where it sends anything, and how to remove one person's trace.

Data flows

Rows pass through and aren't kept

Results are streamed or paged to the caller after masking, and written nowhere unless you turn on the response cache or an export. Parameter values are bound, never logged, never put in a trace; the access log leaves query strings out.

Accountability

Who changed what, recorded so that an edit to the record is itself visible.

Audit

A chain an auditor can check

Each entry carries the hash of the one before. queryapigate audit verify names the first entry that was changed, removed or reordered, and the audit_chain_broken alert fires.

Guide 53 →
Audit

Streamed to your SIEM

Syslog over mutual TLS, or OTLP logs, delivered at least once with nothing lost while the receiver is down. Tested on every push against rsyslog, syslog-ng and the OpenTelemetry Collector; the SIEM's own copy verifies with the same command.

Guide 53 →
Access

Named people, narrow roles

Administrators sign in as themselves, through your identity provider if you like, with the narrowest of four roles. The shared admin key can be sealed as break-glass; using it raises an alert.

Supply chain

From 0.31, every release can be verified before it runs. Releases before 0.31 aren't signed.

  • ✓Each image variant and the Helm chart signed keyless with cosign, by digest, by the release workflow.
  • ✓SLSA provenance naming the commit, an SPDX SBOM, and a GitHub attestation for each image.
  • ✓The release workflow verifies its own signatures before it finishes; a release that doesn't verify fails.
  • ✓Builds pinned: every GitHub Action by commit SHA, base images by digest. A test fails on anything unpinned.
  • ✓Admission controllers (Sigstore policy-controller, Kyverno) shown admitting a signed image and refusing an unsigned one.

Disclosure and scope

Reporting a vulnerability

Please don't open a public issue. Use GitHub's private Report a vulnerability form, or email arcswdev@gmail.com. Expect an acknowledgement within a few days.

Which versions get fixes

Security fixes are made against the latest release. Pin a version, watch the changelog's Security entries, and upgrade; every store upgrades automatically.

Support and versions →

What we don't claim

No SOC 2 or ISO 27001 report: those certify an organisation running a service, and QueryAPIGate runs inside yours, under your controls. What it provides is the evidence your own assessment needs.
