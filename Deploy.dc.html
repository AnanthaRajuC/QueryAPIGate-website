Deploy

Three reference architectures, each one tested in CI

Start with one instance on SQLite. Move to several on PostgreSQL and Redis when you need availability, or install the Helm chart. Instances are interchangeable, so moving between shapes is a configuration change, not a migration project.

Benchmarks

Measured, not promised

One container runs one worker with eight threads; add containers for capacity. These are the numbers the project has measured and checked in.

~2 msAdded by a saved-query call over ad-hoc SQL on a 100-row table (MySQL, p50 6.4 ms vs 4.1 ms).
~300 req/sPer instance at five concurrent callers, one worker with eight threads (MySQL and ClickHouse).
Flat memoryStreaming 1M rows: about 0 MB extra, against 337–988 MB buffered (MySQL).
2.5×Faster on a cache hit than a miss: 5.8 ms vs 14.2 ms median (MySQL).
~1 msTracing cost per request with every request traced; nothing measurable at 10% sampling.
1,016 / 1,000Calls served against a 1,000-call quota on two instances under load, sharing Redis.

Measured with the scripts in benchmarks/ against real databases over real HTTP, between 24 and 30 September 2026; tracing and quota figures from the 0.23 and 0.24 release measurements. Absolute numbers depend on the machine; the shape is the portable claim. The full reports are in benchmarks/results.

Before go-live

Production checklist

The steps between a running server and one you would put in front of a partner.

  1. 01Put it behind TLS: a reverse proxy, with QUERYAPIGATE_TRUST_PROXY set to the number of proxies.
  2. 02Give people their own admin access and seal the shared key: guide 43.
  3. 03Encrypt stored passwords, or use no passwords at all: guide 22, guide 56.
  4. 04Protect /metrics and limit ${VAR} references: guide 58.
  5. 05Scrape metrics and wire up alerts: guide 35; traces: guide 51.
  6. 06Stream the audit log to your SIEM: guide 53.
  7. 07Back up the store and rehearse a restore: guide 33.
  8. 08Run only signed releases, pinned by digest: guide 59; upgrade with guide 34.
