Security

It executes SQL on behalf of whoever can reach it. It is built accordingly.

Read-only by default, scoped by default, recorded always. The controls below are defence in depth around database grants, never a substitute for them. The reasoning behind each one is in the threat model.

Defence in depth

What each layer defends against

Six layers, each stopping a different mistake or attack. The panels replay what each one refuses, and what it lets through.

Identity01

The wrong caller

Scoped API keys, limited to connections and read-only access. Named administrators with the narrowest role that fits: owner, admin, developer, auditor. App users by JWT with JWKS. Console SSO over OIDC + PKCE and MCP OAuth 2.1, both stable since 0.30.

SELECT … WHERE status = :statusbound 'open' ✓

Injection02

Hostile parameters

Parameters are typed and bound, never spliced. A single-statement SQL guard blocks writes and multi-statement injection; it is dialect-aware and exercised by a Hypothesis fuzz suite on every commit. Still: connect with a database account that only has the privileges the API should have.

Policy03

Reaching too far

Per-query and collection grants, table allow-lists per key, write operations and a write ceiling, per-user parameters bound from token claims, rate limits that also throttle key guessing, IP allow-lists and key expiry.

Masking04

Seeing too much

Column masking traced to source columns with sqlglot, so an alias or a join does not leak what the column name hides. Applied before formatting, for every output format and every front door.

Agents05

An agent that acts

MCP write tools do not run. They queue for a person to approve in the Console, with per-agent usage recorded. An agent's call is governed exactly like an app's: same grants, same limits, same log.

audit update_key · mariahash-chained

Record06

Not knowing afterwards

An audit log of who changed what, run history for every query, request IDs in structured logs, Prometheus metrics and alerts. Passwords encrypted at rest with a Fernet key, or kept out of the store as references; the Fernet key and API key secrets are never in a backup.
