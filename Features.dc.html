Features

Write SQL. Configure the query. Apply access controls. Get an API.

A saved query becomes a documented, versioned endpoint with typed, injection-safe parameters and run history. No controller, repository layer, pagination, auth or serialization boilerplate to write for it.

06

Saved queries as endpoints

Each saved query is versioned, has typed parameters with ranges and lengths, and keeps a run history. OpenAPI and a Postman collection are generated, and OpenAPI Generator turns the spec into a typed client in about 50 languages. Group queries into collections and grant access to the whole collection at once.

$ curl 'http://127.0.0.1:5000/q/example_top_films?top_n=2&category=Comedy&format=csv' \
    -H 'X-API-Key: demo-key'
title,category,rating,rentals,rank
Electric Signal,Comedy,PG,977,1
Crimson Garden,Comedy,PG-13,631,2
// query_parameters
{
  "rating":     {"type": "str", "enum": ["G","PG","R"], "default": "PG"},
  "max_length": {"type": "int", "min": 1, "max": 600},
  "title":      {"type": "str", "required": false, "pattern": "[A-Za-z ]+"},
  "customer":   {"type": "int", "from_claim": "sub"}
}

$ curl '/q/films?rating=X&max_length=900' -H 'X-API-Key: demo-key'
400 {"errors": {"rating": "must be one of: G, PG, R",
             "max_length": "must be at most 600"}}
07

Typed parameters, checked before the database

Each :name in the SQL is a bound parameter with a type, bounds, length, enum, pattern and default. A request that breaks a rule gets a 400 listing every problem and never reaches the database. from_claim takes a value from the caller's sign-in token instead of the request, so a user can only ever ask for their own rows.

08

Versions, drafts, publishing

Every saved query has at most one published version: the one /q/<name> runs and the one OpenAPI, MCP and Postman describe. Newer versions are drafts, invisible to callers until published; the admin key can test one by number. Roll back to any earlier version. Older versions stay runnable with ?version=.

Govern

What each caller may reach, decided before any query runs.

09

Access control, per key

A key identifies an application. Every grant below narrows what that key reaches; roles bundle a shape of grants into a reusable template.

connections

Whole connection

Every saved query on it, plus ad-hoc SQL if allowed.

queries · collections

Curated endpoints

Name the saved queries a key may run, one at a time or as a collection. Nothing else answers.

allowed_tables

Table allow-list

Ad-hoc SQL confined to named tables; the SQL is parsed, not pattern-matched.

mask

Column masking

Hash, mask, null or drop named source columns. Traced through aliases, CTEs and joins; refused rather than served unmasked.

allowed_write_ops

Write granularity

Writes off by default. Turn on only INSERT, or UPDATE on one query.

rate_limit · allowed_ips

Budget and origin

A per-key request budget and a list of IPs or CIDR ranges the key may call from.

expires_at · last_used_at

Lifecycle

Time-boxed keys for trials and contractors; alerts before expiry and for keys gone unused.

Authorization: Bearer

Signed-in users

Accept the JWT your app already has (Auth0, Cognito, Keycloak, Azure AD or your own secret). Each user calls as themselves, mapped to a role.

max_concurrent · query_timeout · max_rows

Fair shares

Cap the queries a key runs at once, how long each may run and the rows a call returns, across every instance. Over it: 429 too_many_concurrent.

quota

Usage quotas

Calls and rows per day or month, with X-Quota-Remaining-* headers on every response and an alert before it runs out.

rotate

Secret rotation

Reissue a key's secret while the old one keeps working for a grace period, or zero for a leaked one.

The people and pipelines that manage the server are named, with the narrowest role that fits, so every change in the audit log has a person behind it.

Deliver

Formats, channels and the Console that manages it all.

14

Eight output formats

JSON, NDJSON, CSV, TSV, XML, YAML, XLSX and Parquet. Paginated for typical results; constant-memory streaming with ?stream=true for exports too large to hold in memory.

15

MCP for AI agents

queryapigate mcp exposes saved queries as tools with structured results, ad-hoc tools where allowed, and table and column descriptions. AI clients sign in with OAuth 2.1 through your identity provider, or an API key. Usage is recorded per agent, and write tools wait for a person's approval.

16

Live eventsExp

Server-sent events as queries run, per key if you want. queryapigate events reads every instance's runs from the shared store, woken by a PostgreSQL notification.

17

Scheduled exports

queryapigate export writes a full result to a file, in-process. Atomic rename on completion, non-zero exit on failure, deliveries to S3, GCS, R2 or disk that resume where the last run stopped.

18

Files as tables

Point a connection at a folder or bucket of Parquet, CSV or JSON and each file becomes a view through DuckDB, locked to the paths that connection allows.

19

Response cache

A per-query cache_ttl, in-process by default. With Redis, one cache shared by every instance, surviving restarts.

20

The Console

Manage connections, saved queries, API keys and roles. Run ad-hoc SQL with a schema browser. Review the audit log and alerts, approve agents' writes, manage administrators, exports and quotas, and see who can reach what on the access map. Served from /console, nothing extra to install.

Operate

What you see while it runs, and how it runs in production.

29

Every run recorded, every change audited

Run history is per query and per key, with duration, rows and what was masked. The audit log records who changed what, by named administrator. Alerts are live conditions, worked out on each request and gone once the cause is.

Run history

When, which connection, which key, through which front door, how long, how many rows. Ad-hoc and MCP runs too.

Audit log

Timestamp, actor, action, target and the fields that changed, each entry chained to the one before. Secrets appear as "changed", never their value.

Request IDs

Every response carries X-Request-Id; every log line written for it carries the same.

Alerts

Operations

Store

A SQLite file by default, or PostgreSQL for several instances. Versioned schema with upgrades tested in CI, backup and restore, passwords encrypted at rest.

Scale out

Redis, optional: one cache, one rate-limit budget and one event stream across every instance. If Redis blinks, limits stay enforced per process.

Observe

Structured logs with request IDs, per-key metrics, a Prometheus /metrics endpoint behind a token, a bundled Grafana dashboard, and OpenTelemetry spans Exp from the request to the database call, never holding a value or a row.

Deploy

pip, the image on ghcr (with an -h2 variant including Java), a Helm chart for one pod or several, and a multi-instance Compose setup behind Caddy. Non-root, read-only root filesystem.

Configuration as code

config export, config diff and config apply: the whole setup as one YAML file with no secret in it, reviewed in a pull request and applied all or nothing, by CI or at startup.

Secrets

Passwords encrypted at rest under a key you can rotate, or no password at all: ${file:…}, ${vault:…} and ${aws-sm:…} references, short-lived credentials from Vault or RDS IAM. Experimental.

Prove

The evidence an auditor, a security questionnaire or your platform team asks for. All of it in one place: the Trust center.
