02 · How it works

Five steps between the question and your database

01

Save a query: it's a tool

Write the SQL once in the Console and publish it. Its declared parameters become the tool's typed input schema, and every value is bound, never spliced into the SQL.

Its grant names exactly the queries, connections and tables it needs, and tools/list shows it nothing else. A hosted assistant signs in through your identity provider and acts as that person, their rows and masking included.

03 · Set it up

Connect a client

One URL and a key, or sign-in through your identity provider.

  1. Start the MCP server beside the REST server. Both use the same store and the same rules.
  2. Create a key for the agent in the Console, granted only the queries it needs.
  3. Add a remote MCP server in your client: the URL, and the key as the X-API-Key header. Each client's menu for this differs; look for "remote MCP server" or "custom connector" in its documentation.
shell
$ pip install "queryapigate[server,mcp]"
$ queryapigate serve &
$ queryapigate mcp
the client needs
URL     http://<host>:5001/mcp
Header  X-API-Key: <the agent's key>

The key travels as a header, never in the URL, where it would end up in access logs. Guide 24, step by step →

The official MCP SDK, verified end to end against a running server:

python
import asyncio
from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client

KEY = "your-api-key"

async def main():
    async with streamablehttp_client("http://127.0.0.1:5001/mcp", headers={"X-API-Key": KEY}) as (r, w, _):
        async with ClientSession(r, w) as session:
            await session.initialize()
            tools = await session.list_tools()
            print([t.name for t in tools.tools])
            result = await session.call_tool("example_top_films", {"top_n": 3})
            print(result.structuredContent)

asyncio.run(main())

Results come back as structuredContent with an outputSchema, so your code reads rows, not prose. Guide 24 →

  1. Point the MCP server at your identity provider: Keycloak, Okta, Auth0 or Entra ID. QueryAPIGate checks tokens and issues none; it never sees a password.
  2. Give the assistant the URL. It finds where to sign the user in from the server's metadata, at /.well-known/oauth-protected-resource.
  3. The agent acts as that person: their role, their masking, and only their rows where a parameter is bound to the token.

04 · What it can do

What an agent can do, and what it can't

ReadsChanges nothing
  • Your saved queries, one tool each, typed from their parameters.
  • list_tables and describe_table to explore, masking-aware.
  • execute_sql, always read-only, inside the tables you named.
  • A data dictionary per connection, so it knows what the columns mean.
  • Search by meaning, with an embed parameter and pgvector Exp.
WritesA person approves each one
  • Only through queries you marked for agents.
  • One INSERT, UPDATE or DELETE, never DDL.
  • Runs once, with exactly the arguments approved.
  • In a transaction, rolled back past the rows you allow.
  • The key that asked can never approve it.
RefusedWhatever the prompt says
  • Any query or table outside the agent's grant.
  • A write through execute_sql.
  • A masked column, however the SQL is written; a query it can't trace is refused.
  • A token issued for the REST API, or the reverse.
LimitedWhen an agent loops
  • Rate limits per agent, shared across instances.
  • Daily or monthly quotas on calls and rows.
  • A cap on concurrent queries, and a time limit.
  • 200 rows a result by default (QUERYAPIGATE_MCP_MAX_ROWS), with a note to narrow the query.

06 · Questions

Before you connect an agent

Connecting
Which AI clients work?

Any MCP client that speaks Streamable HTTP and can send a header (for an API key) or follow MCP's OAuth (for sign-in): agent frameworks, IDE assistants and hosted assistants' connectors.

Do I have to rewrite anything for REST?

No, it's the same query. The tool you publish for agents is also GET /q/<name>, with an OpenAPI description, and can be exported on a schedule.

How does a hosted assistant sign in?

Through your identity provider, with MCP's OAuth 2.1. QueryAPIGate checks the tokens and issues none, so it never sees a password, and a token for the REST API is never accepted here.

Safety
Does the AI model ever see database credentials?

No. Agents authenticate to QueryAPIGate; QueryAPIGate reaches your databases with each connection's own credentials, stored encrypted, and never passes a token or password on.

Can an agent read data it shouldn't by rephrasing its question?

Its question doesn't matter; its grant does. It can call only the tools its key or role allows; execute_sql, if granted at all, is read-only and limited to the tables you named; masked columns stay masked however the SQL is written, or the query is refused.

What if it's prompt-injected?

It can ask for anything. It gets only what its grant allows, because the boundary is the server, not the model.

Limits
What happens when an agent loops?

Its rate limit refuses it, its quota stops it for the day or month, and its concurrency cap keeps it from tying up your database, each a clear, machine-readable error it can act on.

What doesn't it do?

Masking isn't available on MongoDB, H2 or generic JDBC connections; a caller with mask rules is refused there. Approved writes run on PostgreSQL, MySQL, SQLite and DuckDB. OAuth needs JWT access tokens signed with an asymmetric key. Semantic search is experimental and PostgreSQL only. And there's no natural-language-to-SQL, by design: it serves the queries you curated.
