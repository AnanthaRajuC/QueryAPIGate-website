Standards and specifications

Built on published standards, not bespoke mechanisms

So a security or platform team can evaluate QueryAPIGate against specs they already trust, and so it drops into existing identity, observability and compliance infrastructure. Each entry names the standard, the RFC or specification, and what QueryAPIGate uses it for.

02 · 9 standards

Authentication and authorization

Agent and user access is standard OAuth 2.0 / OpenID Connect. QueryAPIGate is a resource server that trusts your identity provider, never a parallel password store.

StandardReferenceWhat QueryAPIGate uses it for
OAuth 2.0 / 2.1The OAuth authorization framework ↗The authorization model for the MCP server and JWT-authenticated REST.
OpenID Connect + DiscoveryOIDC Core and Discovery ↗Signing in users from any OIDC provider: Keycloak, Okta, Entra, Auth0, Cognito, Firebase.
Authorization Server MetadataRFC 8414 ↗Finding an identity provider's keys and endpoints from its published metadata.
Protected Resource MetadataRFC 9728 ↗The MCP server advertises itself at /.well-known/oauth-protected-resource: what it is, who issues its tokens, and the scope required.
Resource Indicators for OAuthRFC 8707 ↗The token's audience (aud) must be the server's own URI: a token minted for the MCP server is refused against REST or anything else.
JWT Profile for OAuth Access TokensRFC 9068 ↗Reading scopes from an access token (scope / scp).
Authorization Code + PKCERFC 7636 ↗The Console sign-in flow runs in the browser with PKCE, so the browser never holds a long-lived token.
JWT / JWS / JWK and JWKSRFC 7519 / 7515 / 7517 ↗The token format, its signature, and fetching the provider's public keys from a JWKS URL (cached, refreshed on an unknown key id).
JWT Best Current PracticesRFC 8725 ↗Only the configured algorithms are accepted (RS256), never none, never an HMAC downgrade; exp, iss and aud are validated.

On the roadmap: opaque access tokens via Token Introspection (RFC 7662); JWT access tokens only in the current release.

03 · 7 standards

Audit, observability and operations

How the record leaves the server, and what the tools you already run can read.

StandardReferenceWhat QueryAPIGate uses it for
Syslog protocolRFC 5424 ↗The format of audit entries streamed to a SIEM (facility 13, "log audit").
Syslog over TLSRFC 5425 ↗Encrypted delivery of the audit stream (tls://host:6514).
Syslog over TCP (octet counting)RFC 6587 ↗Framed, loss-detectable delivery over TCP; UDP is refused.
OpenTelemetryOTel tracing and semantic conventions ↗Distributed traces, with connection types mapped to the db.system semantic convention.
Prometheus exposition formatPrometheus text format ↗Metrics at /metrics.
HTTP CachingRFC 9111 ↗Correct Cache-Control semantics, including no-store, so a CDN or caching proxy never serves one caller's rows to another.
Deprecation HTTP headerRFC 9745 ↗Deprecated API routes carry a Deprecation header with the date.
04 · 5 standards

Transport and cryptography

What protects data in flight and at rest, and the primitives behind keys and the audit chain.

StandardReferenceWhat QueryAPIGate uses it for
TLS / mutual TLSX.509 path validation · RFC 5280 ↗Transport security; optional client-certificate authentication, validated strictly against a configured CA.
Fernet (AES-128-CBC + HMAC-SHA256)The cryptography library's Fernet ↗Encrypting stored connection passwords and secrets at rest under QUERYAPIGATE_SECRET_KEY.
SHA-256 / HMAC-SHA256FIPS 180-4 · RFC 2104 ↗API keys and admin tokens are stored only as a SHA-256 hash (the secret is shown once); the audit log is an HMAC-SHA256 hash chain, each entry hashed over the previous.
CORSWHATWG Fetch ↗Controlling which browser origins may call the API.
CIDR notationRFC 4632 ↗Per-key IP allow-lists (allowed_ips).
