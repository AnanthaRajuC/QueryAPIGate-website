How it fits together

From caller to database, through one core

Every front door runs the same checks, so an AI agent's call is governed exactly like an app's. The core is the product; the front doors and drivers plug into it. Write the SQL once; QueryAPIGate publishes it as a REST endpoint, an MCP tool, a live event stream and a scheduled export, and reports every call to the systems you name.

Who callsApps, partners, AI agents, people, pipelinesBackends and dashboards, scoped partner keys, any MCP client, the Console through your SSO, cron and Kubernetes CronJobs.
↓
Front doorsREST · MCP · live events · exports · /api/v1One endpoint per saved query, saved queries as agent tools, server-sent events, scheduled exports and the management API.
↓
AsksIdentity provider · secret provider · shared stateTokens are checked against your identity provider over JWKS and OIDC, credentials come from Vault or AWS, and Redis or the PostgreSQL store hold cache, limits and quotas across instances. Answered, never stored.
↕
The governed coreIdentity → policy → execution → recordIdentify the caller, apply its limits, check the grant, validate parameters, guard the SQL, run it, mask and format, record it.
↓
Your dataDatabases, files and deliveriesPostgreSQL, MySQL, SQLite, DuckDB, ClickHouse and MongoDB, plus Trino, H2 and JDBC; Parquet, CSV and JSON in S3, GCS or R2.

Reports toLog · traces · metrics · auditEach call goes to stdout, OpenTelemetry, Prometheus and your SIEM as counts, timings and audit entries, never a row or a credential.

Client libraries

A typed client in your team's language, generated in one command

Every server publishes a complete OpenAPI 3.0 spec, checked against the official validator in CI, with each saved query as its own typed endpoint. Point OpenAPI Generator at it and get a client in any of its roughly 50 languages: methods named after your queries, parameters typed from their rules, nothing written by hand.

Governed, not just exposed

Run it

A running server in minutes, wherever you run things

The same server three ways. Load the examples and the first request works at once: a small generated database and four worked APIs. The image and the chart are signed, with provenance and an SBOM. Reference architectures and measured performance →

pip

On your machine

Python 3.11 or later. SQLite included; add drivers as extras.

Install and extras →
run · pip 
$ pip install queryapigate
$ export QUERYAPIGATE_API_KEY=demo-key
$ queryapigate examples load
$ queryapigate serve
# http://127.0.0.1:5000 · Console at /console
docker

In a container

Every driver except H2, plus Redis, MCP and tracing. -h2 tags add Java for H2 and JDBC.
