How it fits together

From caller to database, through one core

Every front door runs the same checks, so an AI agent's call is governed exactly like an app's. The core is the product; the front doors and drivers plug into it.

Client libraries

A typed client in your team's language, generated in one command

Every server publishes a complete OpenAPI 3.0 spec, checked against the official validator in CI, with each saved query as its own typed endpoint. Point OpenAPI Generator at it and get a client in any of its roughly 50 languages: methods named after your queries, parameters typed from their rules, nothing written by hand.

TypeScript✓Python✓Java✓GoC#KotlinSwiftRustPHPRubyDartScala+ about 40 more

✓ generated and called against a live server. Generate with a partner's key and their client contains only the queries that key may call. Regenerate when you publish a new query version.

Governance

Governed, not just exposed

Read-only by default. A single-statement SQL guard blocks writes and multi-statement injection unless a connection or key explicitly opts in. Every call passes the same four controls whether it comes from an app, a partner key or an AI agent. The security model →

Run it

A running server in minutes, wherever you run things

The same server three ways. Load the examples and the first request works at once: a small generated database and four worked APIs. The image and the chart are signed, with provenance and an SBOM. Reference architectures and measured performance →

pip

On your machine

Python 3.11 or later. SQLite included; add drivers as extras.

Install and extras →
run · pip 
$ pip install queryapigate
$ export QUERYAPIGATE_API_KEY=demo-key
$ queryapigate examples load
$ queryapigate serve
# http://127.0.0.1:5000 · Console at /console
docker

In a container

Every driver except H2, plus Redis, MCP and tracing. -h2 tags add Java for H2 and JDBC.
